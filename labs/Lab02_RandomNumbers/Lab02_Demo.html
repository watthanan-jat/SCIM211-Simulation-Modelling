2.3 Why We Use np.random.default_rng()¶

NumPy recommends default_rng() for new code. It constructs an explicit Generator, backed by PCG64 in the installed NumPy version. Separate objects have separate state, can be passed into functions, and do not silently depend on one shared global NumPy generator.

default_rng does not mean “proven random.” Period and dependence still matter.

2.4 Choosing a Generator Method¶

Need Method
Uniform probability input rng.random(n)
Whole-number outcome rng.integers(low, high, n)
Category or item rng.choice(items, n)
Random ordering rng.shuffle(array)
Normal measurement rng.normal(mean, sd, n)
Positive waiting time rng.exponential(mean, n)

Lab 2 focuses on uniform values. Later labs model other inputs.

2.5 What Is a Seed?¶

A seed initializes internal generator state. It is not the first generated number, a sample-size setting, or a quality score.

  • Same algorithm plus same seed reproduces the same starting stream.
  • Different seeds normally produce different starting streams.
  • Nearby seed numbers do not imply nearby outputs.
  • A fixed seed supports teaching, debugging, and comparison.
  • default_rng() without a seed obtains fresh operating-system entropy and is not exactly reproducible.
  • Recreating the same seed inside every replication would incorrectly repeat the same stream.

Demo 4: Build a Reusable LCG¶

In [86]:
def make_lcg(a, c, m, x0, n):  # Define one reusable LCG command
    x_values = []  # List for X
    u_values = []  # List for U
    x = x0  # Seed
    for i in range(n):  # Repeat the LCG calculation n times
        x = (a * x + c) % m  
        u = x / m  
        x_values.append(x)  
        u_values.append(u) 
    return pd.DataFrame({"X": x_values, "U": u_values})

Demo 5: Find the Period¶

Exact integer states should be used for period detection. Rounded uniform values can create false matches. A short period repeatedly reuses simulation inputs.

In [91]:
def find_lcg_period(a, c, m, x0):  # Define a function that finds the LCG period
    seen = []  
    x = x0  
    while x not in seen:  # Continue until an exact state appears again
        seen.append(x)    # Save the state before moving to the next one
        x = (a * x + c) % m  
    first_position = seen.index(x)  
    return len(seen) - first_position  # Return the repeating cycle length

Demo 9: Speed and Scale¶

We compare two ways to generate the same 50,000 uniform values:

Method What Python does Number of generator calls written by us
Method 1: Python loop Repeats rng.random() once per iteration 50,000
Method 2: NumPy vectorised Requests the complete array with rng.random(50000) 1

For a fair comparison, both methods use:

  • seed 42;
  • the same NumPy generator type;
  • exactly 50,000 values; and
  • the same timing function.

We compare elapsed time and confirm that the two methods produced identical values.

In [ ]:
timing_size = 50000  # Set the same number of values for both methods

Method 1: Generate One Value at a Time¶

This method crosses from Python into NumPy 50,000 times. The final expression displays the elapsed seconds automatically.

In [ ]:
loop_rng = np.random.default_rng(42)  
loop_start = time.time()  
loop_values = []  # List for the generated values
for i in range(timing_size):  
    loop_values.append(loop_rng.random())  # Generate and store one scalar value
loop_time = time.time() - loop_start  
loop_time

Method 2: Generate the Complete Array¶

This method makes one vectorised request. The final expression displays the elapsed seconds automatically.

In [ ]:
vector_rng = np.random.default_rng(42)  # Recreate the same starting state for the vectorised method
vector_start = time.time()  
vector_values = vector_rng.random(timing_size)  # Generate all values in one NumPy call
vector_time = time.time() - vector_start  
vector_time

Demo 10: Model a Strong Interpretation¶

Mini-9 covers its nine possible values evenly, so its histogram initially looks acceptable. However, its period is only nine and the successive-value plot contains only a few repeated transitions. I would use NumPy for a real simulation because the sample contains many distinct values and no obvious low-dimensional pattern. Vectorised NumPy generation is also faster when many values are required. These checks do not prove perfect randomness, but they identify serious weaknesses in Mini-9.

Common Errors¶

  • Resetting x = x0 inside the LCG loop.
  • Forgetting modulo or scaling.
  • Detecting repetition with rounded values.
  • Plotting arrays of unequal lengths.
  • Treating a balanced histogram as proof of independence.
  • Writing [0, 1] instead of [0, 1).
  • Timing methods with different seeds or sample sizes.
