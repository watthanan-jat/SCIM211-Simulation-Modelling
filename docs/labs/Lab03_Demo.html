Algorithm — Discrete Inverse Transform¶

For a discrete random variable with ordered possible values$$x_1,x_2,\ldots,x_k,$$first calculate the cumulative probabilities$$F(x_i)=\sum_{j=1}^{i}p(x_j).$$

Algorithm

  1. Generate $U\sim U(0,1)$.
  2. Find the smallest $x_i$ such that$$F(x_i)\ge U.$$
  3. Return that value $x_i$.

In the code below:

  • np.cumsum(probabilities) constructs the CDF values $F(x_i)$.
  • np.searchsorted(a,u, side="left") finds the first cumulative cut point that is at least $U$ (step 2).
  • indexing demo_drinks[category_index] performs Step 3 and returns the category.

Algorithm — Inverse Transform¶

Let the target random variable $X$ have CDF $F$.

Algorithm

  1. Generate$$U\sim Uniform(0,1).$$
  2. Compute$$X=F^{-1}(U).$$
  3. Return $X$ as the desired random variate.

For an exponential random variable with rate $\lambda$,$$F(x)=1-e^{-\lambda x}.$$

Solving $U=F(X)$ gives$$X=-\frac{1}{\lambda}\ln(1-U).$$

The next code cell implements exactly these three steps: start from $U$, apply the inverse CDF, and obtain an exponential service time.

Checkpoint — Algorithm versus Package Generator¶

Chapter 5 describes how a target random variate can be constructed from uniform random numbers. NumPy also provides specialised, tested generators such as

rng.exponential(scale=...)

The purpose of this comparison is to separate two ideas:

  • algorithmic understanding: manually apply $X=F^{-1}(U)$;
  • practical simulation: use a library generator once we understand the model and its parameterisation.

Correctness is judged by the generated distribution, not by expecting the two methods to produce identical element-by-element sequences.

Algorithm — Continuous Acceptance–Rejection¶

Suppose the target PDF is $f(x)$. Choose an easy proposal PDF $g(x)$ and a constant $c$ satisfying

$$f(x)\le c\,g(x)\qquad\text{for all }x.$$

Algorithm

  1. Generate a proposal $Y$ from the distribution with PDF $g$.
  2. Independently generate$$U\sim U(0,1).$$
  3. Accept $Y$ if$$U\le \frac{f(Y)}{c\,g(Y)}.$$If accepted, set $X=Y$ and stop. Otherwise reject $Y$ and return to Step 1.

Demo Example¶

The demo target is

$$f(x)=3x^2,\qquad 0\le x\le1.$$

Choose the uniform proposal

$$g(x)=1,\qquad 0\le x\le1.$$

Because$$\max_{0\le x\le1}f(x)=3,$$we can choose $c=3$. Therefore

$$\frac{f(Y)}{c\,g(Y)}=\frac{3Y^2}{3(1)}=Y^2.$$

So Step 3 becomes simply

$$\boxed{U\le Y^2}.$$

That is why the code below tests u <= x**2.

The theoretical acceptance probability is $1/c=1/3$, so the expected number of proposals per accepted value is $c=3$.

Demo 6: Accept-Reject Sampling with a Different Target¶

Combining Algorithms in One Model¶

A realistic simulation input can require more than one random-variate generation step.

For each customer in this demo:

  1. Generate the drink category using a discrete distribution.
  2. The selected drink determines the exponential mean $\mu_j$.
  3. Generate the service time from the corresponding continuous distribution.

Mathematically,$$D\sim\text{Categorical}(p_1,p_2,p_3),$$followed by$$T\mid D=j\sim\text{Exponential}(\text{mean } \mu_j).$$

This is a conditional model: the second random variable depends on the outcome of the first.

Demo 7: Combine the algorithms — category first, then conditional service time¶

For each customer:

  1. Generate a drink category using the discrete inverse-transform algorithm.
  2. Use that selected drink to determine the exponential mean service time.
  3. Generate a new independent uniform random number for service time.
  4. Apply the continuous inverse-transform algorithm.

Mathematically,

$$D\sim \operatorname{Categorical}(p_1,p_2,p_3),$$

then, conditional on the selected drink,

$$T\mid D=j\sim \operatorname{Exponential}(\text{mean } \mu_j).$$

So the model dependency is

$$U_1 \longrightarrow D \longrightarrow \mu_D\longrightarrow U_2 \longrightarrow T.$$

The important point is that the service-time distribution depends on the drink category, so we must generate the category before generating its service time.

Algorithm before we code¶

For each customer $i$:

Generate U1 ~ Uniform(0,1)Use U1 and the drink CDFto determine drink DiLook up the corresponding mean μiGenerate a NEW U2 ~ Uniform(0,1)Set Ti = -μi log(1-U2)Return (Di, Ti)

In mathematical notation,

$$U_{1,i}\longrightarrowD_i\longrightarrow\mu_i\longrightarrowU_{2,i}\longrightarrowT_i.$$

The two uniforms have different jobs:

  • $U_{1,i}$ decides which category customer $i$ belongs to.
  • $U_{2,i}$ determines the service time within that category's exponential distribution.

We therefore generate a new $U_2$ rather than reuse $U_1$. This preserves the intended conditional model: after the category has been selected, the service time is generated from the distribution associated with that category.

Now compare each line of this algorithm with the Python implementation below.

Demo 8: From category-level workload to the overall expected service time¶

Demo 7 showed how to generate the mixture model:

$$U_1 \longrightarrow D \longrightarrow \mu_D\longrightarrow U_2 \longrightarrow T.$$

Now we ask a different question:

Which drink contributes most to the expected service workload, and how do the category-level contributions combine into the overall mean service time?

For drink category $j$,

$$p_j=P(D=j)$$

is the probability that a customer orders drink $j$, while

$$\mu_j=E[T\mid D=j]$$

is the mean service time given that drink $j$ was ordered.

The expected workload contribution of category $j$ per arriving customer is

$$\boxed{p_j\mu_j}.$$

This combines two effects:

  • $p_j$: how often the category occurs,
  • $\mu_j$: how long it takes when it occurs.

A category can therefore contribute strongly to workload either because it is common, because it is slow, or both.

Law of Total Expectation¶

Adding the workload contributions from all categories gives

$$E[T]=\sum_j P(D=j)E[T\mid D=j]=\boxed{\sum_j p_j\mu_j}.$$

So the individual quantities $p_j\mu_j$ are the pieces that make up the overall expected service time.

This is the key distinction:

$$\boxed{\mu_j=\text{mean service time for category }j}$$

whereas

$$\boxed{p_j\mu_j=\text{expected workload contribution from category }j\text{ per arriving customer}.}$$

Interpreting the table¶

Do not identify the largest workload category by looking only at (\mu_j).

The relevant comparison is

$$p_j\mu_j.$$

A drink may have the longest mean service time but still contribute less total workload if it is rarely ordered.

The total expected service time is simply the sum of the category-level contributions:

$$E[T]=\sum_j p_j\mu_j.$$

Why no new simulation is needed here¶

For this scenario comparison, the model already specifies the category probabilities (p_j) and conditional means (\mu_j).

Therefore,

$$E[T]=\sum_j p_j\mu_j$$

can be calculated exactly.

A second simulation would only add Monte Carlo noise to a quantity we can already compute analytically.

This is an important modelling principle:

Simulate when necessary; calculate analytically when the model gives an exact quantity.

Common Errors¶

  • Passing the exponential rate as NumPy's scale; scale is the mean.
  • Omitting the minus sign in the inverse-transform formula.
  • Expecting a sample mean to equal the model mean exactly.
  • Treating rejected proposals as mistakes or excluding them from the proposal count.
  • Using probabilities that do not sum to 1.
  • Generating service times before assigning categories.
  • Making a queue claim from service inputs before modelling arrivals and servers.
