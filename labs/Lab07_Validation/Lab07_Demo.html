Theory 1: Why input modelling matters (Chapter 9)¶

A simulation needs input distributions: gaps between arrivals, service times, demand. If we estimate a quantity by

$$ \widehat\theta_n=\frac1n\sum_{i=1}^nh(X_i), $$

the law of large numbers makes $\widehat\theta_n$ converge to the expectation under the distribution we put into the simulation. If that input distribution is wrong, the simulation converges to the wrong target, however many runs we make.

So before fitting anything, check the raw data:

Check Question
Range Are all times positive?
Outliers Are there impossible or suspicious values?
Units Are all values in the same unit (minutes)?
Missing values Are any entries missing?

Theory 2: Fitting an exponential distribution (Chapter 9)¶

Maximum likelihood. If $X\sim\mathrm{Exponential}(\lambda)$, the density is $f(x;\lambda)=\lambda e^{-\lambda x}$ for $x\ge0$. For data $x_1,\dots,x_n$ the log-likelihood is

$$ \ell(\lambda)=n\ln\lambda-\lambda\sum_{i=1}^nx_i , \qquad \frac{d\ell}{d\lambda}=\frac n\lambda-\sum_{i=1}^nx_i=0 \ \Longrightarrow\ \widehat\lambda=\frac{n}{\sum x_i}=\frac1{\bar x}. $$

So the fitted exponential has mean $\bar x$ and rate $1/\bar x$.

Fitting is not validating. Any positive data set has a mean, so we can always fit an exponential with the right mean. Whether the shape is right is a separate question.

The empirical distribution function (ECDF) uses the data directly:

$$ F_n(x)=\frac1n\times(\text{number of observations}\le x). $$

At the $k$-th smallest observation, $F_n$ jumps to $k/n$. Comparing $F_n$ with the fitted CDF $F(x)=1-e^{-\widehat\lambda x}$ shows where the model fits well or badly.

Theory 3: The chi-square goodness-of-fit test (Chapter 9)¶

$$ H_0:\ \text{the data follow the specified distribution},\qquad H_1:\ \text{they do not}. $$

  1. Divide the possible values into $k$ bins (expected counts should usually be at least 5).
  2. Count the observed frequency $O_i$ in each bin.
  3. Compute the expected frequency $E_i=n\,\mathbb P(X\in\text{bin }i)$ under $H_0$.
  4. Compute $\displaystyle\chi^2=\sum_{i=1}^k\frac{(O_i-E_i)^2}{E_i}$.
  5. Use $\mathrm{df}=k-1-m$, where $m$ is the number of parameters estimated from the same data.
  6. Reject $H_0$ if $\chi^2$ is larger than the critical value $\chi^2_{0.05,\mathrm{df}}$.

This is the frequency test from Chapter 4 (Lab 2), with expected counts from any distribution.

Theory 4: Output analysis (Chapter 9)¶

One replication (one simulated day, or one long run) gives one observation $X_i$, for example the average wait that day. With $n$ independent replications,

$$ \bar X=\frac1n\sum_{i=1}^nX_i,\qquad S^2=\frac1{n-1}\sum_{i=1}^n(X_i-\bar X)^2,\qquad \bar X\pm1.96\,\frac{S}{\sqrt n}\ \ \text{(approximate 95\% CI)}. $$

For a probability (each replication gives 1 if an event happens, 0 if not), use $\widehat p\pm1.96\sqrt{\widehat p(1-\widehat p)/n}$.

Two lecture examples, computed in Python:

Demo 4: The coffee shop as an M/M/1 queue¶

Chapters 7 and 10 use a coffee shop with one barista: customers arrive at $\lambda=6$ per hour and the barista serves at $\mu=8$ per hour, both exponential. In minutes, the mean gap is $60/6=10$ and the mean service time is $60/8=7.5$.

The function below is the Lab 5 model: generate all gaps first, then all service times, then apply the first-come-first-served rule $\text{start}_i=\max(\text{arrival}_i,\ \text{end}_{i-1})$. It returns every customer's wait. The argument service_model lets us change the input model later (Demo 7): "exponential", or "constant" (every service takes exactly the mean).

In [10]:
def simulate_queue(n_customers, mean_gap, mean_service, service_model, rng):
    # Waiting times (minutes) of n_customers in a one-server, first-come-first-served queue.
    gaps = rng.exponential(mean_gap, n_customers)          # all gaps first
    arrival = np.cumsum(gaps)                               # arrival times = running totals of the gaps

    if service_model == "exponential":
        service = rng.exponential(mean_service, n_customers)
    else:                                                    # "constant": every service takes the mean
        service = np.full(n_customers, mean_service)

    wait = np.zeros(n_customers)
    previous_end = 0.0                                       # the shop starts empty
    for i in range(n_customers):
        start = max(arrival[i], previous_end)
        wait[i] = start - arrival[i]
        previous_end = start + service[i]
    return wait


rng = np.random.default_rng(DEMO_SEED)
one_run = simulate_queue(50, 10, 7.5, "exponential", rng)
print(f"one morning of 50 customers: average wait = {np.mean(one_run):.2f} minutes")

one morning of 50 customers: average wait = 10.15 minutes

Theory 5: Verification and steady state (Chapters 7, 9 and 10)¶

Verification asks: did we build the model correctly in the computer? Run the code on a case whose answer is known exactly. For a stable M/M/1 queue, Chapter 7 gives the long-run mean wait in the queue

$$ \rho=\frac\lambda\mu=\frac68=0.75,\qquad W_q=\frac{\rho}{\mu-\lambda}=\frac{0.75}{8-6}=0.375\ \text{hours}=22.5\ \text{minutes}. $$

$W_q$ is a steady-state value: what happens if the shop has been running for ever. A run that starts empty is biased at first (Chapter 8 and Chapter 9). The remedy from Chapter 9 is replication/deletion: run $R$ independent long runs, delete a warm-up from each, and average the rest. The $R$ run averages are independent, so the confidence interval of Theory 4 applies.

Validation asks a different question: is this the right model for the real shop? A pass on verification says nothing about that.

Demo 6: How many replications? A stopping rule (Chapter 9)¶

Chapter 9's rule: choose a target margin $d$, generate at least 100 replications, then keep adding replications until

$$ \frac{1.96\,S_k}{\sqrt k}<d . $$

We use $d=0.5$ minutes and add 10 replications at a time.

In [14]:
d = 0.5
averages = []
for r in range(1, 101):                                       # start with 100 replications
    rng = np.random.default_rng(DEMO_SEED + r)
    averages.append(np.mean(simulate_queue(2000, 10, 7.5, "exponential", rng)[200:]))

margin = 1.96 * np.std(averages, ddof=1) / np.sqrt(len(averages))
print(f"after k = 100: margin = {margin:.3f}")

while margin >= d:                                            # keep going until the margin is below d
    for i in range(10):                                       # add 10 more replications
        r = len(averages) + 1
        rng = np.random.default_rng(DEMO_SEED + r)
        averages.append(np.mean(simulate_queue(2000, 10, 7.5, "exponential", rng)[200:]))
    margin = 1.96 * np.std(averages, ddof=1) / np.sqrt(len(averages))

print(f"stopped at k = {len(averages)}: mean = {np.mean(averages):.2f}, margin = {margin:.3f}")

after k = 100: margin = 1.070

stopped at k = 360: mean = 22.18, margin = 0.494

Note. After 100 replications the margin is about 1.0 minute; halving it to 0.5 needed about four times as many replications (the margin shrinks like $1/\sqrt k$). Chapter 9's activity gives the same idea as a formula: with $S_k\approx3.5$ and $d=0.5$, $k\ge(1.96\times3.5/0.5)^2=188.2$, so about 189 replications. Here the run averages vary more ($S_k\approx4.7$), so the formula gives $(1.96\times4.7/0.5)^2\approx340$: close to where the loop stopped.

Theory 6: Validation by sensitivity analysis, and comparing two scenarios¶

Sensitivity analysis (Chapter 10) asks: do the conclusions change when an uncertain assumption changes? Here the uncertain assumption is the service-time model. We keep the mean service time at 7.5 minutes and compare:

  • exponential service times (very variable: CV = 1), and
  • constant service times (no variability: CV = 0).

Comparing two scenarios (Chapter 9). Let $X_{1i}$ and $X_{2i}$ be the outputs of replication $i$ under the two models.

  • With independent random numbers: $(\bar X_1-\bar X_2)\pm1.96\sqrt{S_1^2/n+S_2^2/n}$.
  • With the same random numbers in both (common random numbers): use the differences $D_i=X_{1i}-X_{2i}$ and $\bar D\pm1.96\,S_D/\sqrt n$. Because the two outputs move together, this interval is usually narrower. Chapter 9's example: one barista versus two gives $3.8\pm0.72$ with independent runs, but $3.8\pm0.40$ with paired runs.

Demo 8: A strong interpretation¶

Under the M/M/1 assumptions ($\lambda=6$, $\mu=8$ per hour), the simulated long-run mean wait is about 22.5 minutes, and 30 replications with a warm-up deleted give an interval that contains the exact value: the code passes a verification check. That says the code is right for the assumed model, not that the model is right for the shop. Keeping the mean service time at 7.5 minutes but removing its variability roughly halves the mean wait, so the recommendation depends strongly on the shape of the service-time distribution. Before advising on staffing, the shop should collect enough service times to check that shape (histogram, ECDF, chi-square test), and report every result with a confidence interval.

A strong recommendation connects: the decision, with numbers and intervals; what was verified; what was validated, and how sensitive the result is to the input model; one limitation; and a practical next step.

Final theory map¶

Input modelling: check the raw data; fit $\widehat\lambda=1/\bar x$ for an exponential; compare the ECDF with the fitted CDF; the CV of an exponential is 1.

Chi-square test: $\chi^2=\sum(O_i-E_i)^2/E_i$, $\mathrm{df}=k-1-m$; reject if $\chi^2>\chi^2_{0.05,\mathrm{df}}$; the largest contributions show where the model fails.

Output analysis: one replication = one observation; $\bar X\pm1.96\,S/\sqrt n$; for a probability $\widehat p\pm1.96\sqrt{\widehat p(1-\widehat p)/n}$; stop when $1.96\,S_k/\sqrt k<d$.

Steady state: delete a warm-up; replication/deletion.

Verification versus validation: the right code (compare with $W_q$) versus the right model (data, sensitivity, comparison with the real shop).

Common errors¶

  • Fitting the mean and calling the model validated.
  • Forgetting to subtract estimated parameters from the degrees of freedom.
  • Using np.std without ddof=1 for a sample SD.
  • Reporting one run's average as the answer.
  • Comparing $W_q$ (steady state) with short runs that start empty.
  • Thinking more replications fix a wrong input model.
